## Summary

v0.2.3 을 3 환경(dev/qa/prod)에 배포한 직후, PM 의 실사용 테스트 + 추가 UX 리서치로 확인된 4 CRITICAL 과 6 UX/정합성 개선의 번들. 어느 하나도 해소되지 않으면 사용자/RL 이 정상 훈련 사이클을 돌리거나 결과를 해석할 수 없는 상태였다:

1. 훈련 중 새로고침 → Start 버튼만 보이고 Stop 이 사라짐 → 개입 불가
2. Stop/Pause/Level 버튼이 시각적 무반응 + 새로고침 시 그래프/최근경기 패널 공백
3. Stop 클릭이 훈련을 실제로 중단시키지 않음 + step/episode 카운터가 0/0 에 고착
4. weak RL policy 의 self-toss 로 rally 가 무한 루프 → 다음 게임으로 진행 불가 (엔진 deadlock)

여기에 v0.2.3 이후 식별한 다음 개선 항목을 추가 번들:
- 메트릭 차트가 새로고침 전후 같은 step 에서 다른 Y 값 (WS raw vs REST 1-min bucket AVG 값 도메인 불일치)
- "Enter 강타 unused" / 원본의 hyper-ball 시각 피드백 누락 — `ball.is_power_hit` authoritative flag + 3-slot trail 로 원본 스프라이트 거동 재현
- Training Controls L1-L5 버튼과 Hyperparameters dropdown 사이의 bot_level 두 store 충돌 → Option A (status.botLevel single source) 로 정리
- `/timeseries` 엔드포인트 확정 (FE-8 대시보드 하이드레이션 최종 계약)
- 관련 인프라 수정: `promote.sh` backend container force-recreate 누락 보강

모두 같은 deploy window 에서 dev 에 착지했고 DevOps 가 3 환경에 byte-identical bundle `index-DqBsWzf5` 로 단일 배포 완료.

## Hotfixes & Improvements Included

### 1. FE REST hydration on mount + reconnect — `bd6cea5a`
**Problem**: `useTrainingStateImpl` 가 `status={state:'stopped',...}` 하드코딩으로 시작하고, `training:status` WS 메시지는 *state change* 시에만 broadcast 되었다. 결과: 훈련이 **실제로 돌아가는 중**에 페이지를 새로고침하면 UI 가 stopped 상태로 고착 → Start 버튼만 보이고 Stop 이 사라져 사용자가 개입 불가.

**Fix**: `useTrainingStateImpl` 에 2 개 effect 추가.
1. Mount 시 `GET /api/training/status` → 첫 paint 가 서버 실제 상태 반영 (WS 타이밍 독립).
2. `connectionState` 가 `'connected'` 로 전환될 때마다 re-fetch → 중간 세션 재연결 복구.

REST 에러는 best-effort 처리, WebSocket 은 live channel 로 유지.

### 2. FE optimistic Stop/Pause/level + REST hydration for graphs/games — `06519a42`
**Problem**: dev (`http://<frontend-host>:3000/`) 에서 PM/QA 가 연달아 리포트한 4 건:
- Stop 클릭 → UI 시각적 무반응 (running 상태 유지)
- Pause 클릭 → 백엔드에 `training:pause` WS 핸들러 자체가 없어 드롭
- 새로고침 → 그래프/최근경기 패널 공백 (mount 시 REST seed 없음)
- Bot Level L1..L5 버튼 → 현재 선택 표시 없음, "죽은 버튼" 느낌

**Fix**:
- `useTrainingState` 의 `wsSend` 를 optimistic local state update 로 감쌈 → stop/pause/resume/set_level 이 클릭 즉시 UI 반영. 백엔드 echo `training:status` 가 reconcile.
- Mount 시 `/api/training/metrics/aggregate?bucket=1m` + `/api/games?limit=20` + 게임 캔버스 REST seed 로 새로고침 후 즉시 복원.
- Bot Level 버튼 active state 명시적 렌더링.

### 3. BE stop/pause 실제 중단 + step/episode metrics broadcast — `ee1b48ae`
**Problem**: QA 가 Stop/Pause 클릭 후에도 훈련 worker thread 가 계속 돌고, step/episode counter 가 0/0 에 고착됨을 보고. UI optimistic update 만으로는 실제 중단되지 않는 근본 문제.

**Fix**:
1. `TrainingManager` 가 `threading.Event` pair (stop + pause) 를 SB3 `CallbackList` 를 통해 worker thread 에 연결 → user intent 가 실제로 unwinding 시킴.
2. `LiveFrameCallback` 이 `TrainingManager.last_frame` 을 갱신 → 새로고침 시 다음 frame tick 기다리지 않고 캔버스 즉시 repaint.
3. `GET /api/training/status` 에 `bot_level`, `experiment_id`, `started_at` (ISO-8601 UTC) 필드 추가.
4. 상태변이 REST 엔드포인트(`POST /api/training/{stop,pause,resume,set_level}`) 가 `training:status` broadcast 를 수행하도록 통일 — WS control surface 와 REST control surface 의 대칭화.

REST 추가 (refresh resilience 목적):
- `POST /api/training/stop` — force=True stop, broadcasts status
- `POST /api/training/pause` — sets pause event, broadcasts status
- `POST /api/training/resume` — clears pause event, broadcasts status
- `POST /api/training/set_level` — updates bot level, broadcasts status

### 4. Rally-timeout safety valve + RL truncation — `913fca5f`
**Problem**: weak RL policy 가 자기 쪽에서 공을 무한히 self-toss 하여 rally 가 끝나지 않음 → 다음 게임으로 진행 불가. 선행 reward-shaping 패스(`f8ea6126`) 는 해당 행동에 penalty 를 부과했으나 에피소드 bound 는 제공하지 않아 agent 가 reward farm 으로 악용 가능했음.

**Fix (options C + D 조합)**:
- **(C) 엔진 net-crossing timeout**
  - `GameState` 에 `frames_since_net_crossing` + `round_ended_by_timeout` 필드 추가
  - `step()` 이 매 프레임 `NET_PILLAR_X` 기준 이전/현재 ball.x 교차 여부를 비교, 어느 방향이든 crossing 시 counter 를 0 으로 reset
  - `RALLY_MAX_FRAMES` (600, 10s @ 60fps) 경과 시 `_handle_rally_timeout()` 이 ball 미보유 side 에 point 부여하고 fresh serve
  - `round_ended_by_timeout` 를 state 에 남겨서 RL env 가 natural concede 와 safety-valve exit 를 구분 가능
- **(D) env 에피소드 truncation**
  - `env.py` 가 `round_ended_by_timeout` 를 `getattr` 로 방어적으로 읽고 기존 local `_frames_since_crossing` stall counter 와 OR
  - `truncated=True` + `_RALLY_TIMEOUT_PENALTY` 적용 → PPO 가 stall 을 loss-shaped terminal 로 학습
  - `info["engine_rally_timeout"]` 텔레메트리 노출

`backend/tests/test_engine.py::TestRallyTimeout` 5 케이스 신설. 전체 스위트 352 passed (unrelated `test_models_empty` 1건 pre-existing failure).

### 5. Metrics chart REST hydration 비활성화 (P0 stopgap) — `eaec7ba8`
**Problem**: 훈련 메트릭 차트가 새로고침 전후 같은 X(step) 에서 다른 Y 값을 보이던 일관성 버그. 원인 분석 결과:
- WS `training:metrics` = per-snapshot raw (즉시값)
- REST `/metrics/aggregate` = 1-min bucket AVG (시간 기반 집계)

두 값 도메인이 다르므로 FE 에서 혼합 시 동일 step 에 대해 다른 Y.

**Fix (P0 stopgap)**: FE 가 REST 하이드레이션을 비활성화하고 WS 만을 신뢰. 실제 해결은 `/timeseries` (hotfix #6) 로 step-indexed 포인트를 받아 REST↔WS 일치를 회복.

### 6. `/timeseries` 엔드포인트 — `581e2a58`
**Problem**: 새로고침 후 차트가 full trailing window 가 아닌 WS 도착 이후 포인트만 보임. REST 하이드레이션은 필요하지만 `/aggregate` 는 값 도메인이 달라 사용 불가.

**Fix**:
- `GET /api/training/metrics/timeseries` 신설, `{step, value, timestamp}` shape 반환
- `timestamp`: 서버-스탬프 ISO-8601 UTC, persist 이후 non-null
- default limit 100 → 1000 확장 (trailing window 재생)
- `MetricsService.recent_points` 가 `timestamp` projection + naive datetime → UTC 정규화

FE-8 대시보드 하이드레이션 최종 계약.

### 7. Hyper-ball (power hit) 시각 피드백 — `3b4303df` + `d48d8a15` + `33f6b868` + `15c702ca`
**Problem**: FE 가 `ballSpeed > 25` heuristic 로 power hit 을 감지했으나:
- 실제 power hit 다수 누락
- 잔류 속도에서 false positive
- "Enter 강타 unused" 사용자 피드백

원본 gorisanson/pikachu-volleyball (1997) 은 `ball.isPowerHit` flag 를 권위적으로 사용 (physics.js:725/727, view.js:513).

**Fix**:
- **엔진 권위 플래그 포트** (`3b4303df`): `BallState.is_power_hit` 추가 + WS `training:frame` payload 에 emit
- **Optional 타입 정의** (`d48d8a15`): FE `BallState.isPowerHit` + `previousX/Y` + `previousPreviousX/Y` Optional — BE emitter 도착 전까지 undefined 로 기존 동작 유지
- **Trail 렌더링** (`33f6b868`): `computePowerHitTrail(ball, history)` 순수 함수 + 3-slot 히스토리 버퍼로 원본 sprite 위치 재현. `powerHitTrail.test.ts` 단위 스위트 신설
- **키보드 spec 재조사 문서화** (`15c702ca`): 현 FE 는 spectator-only 로 키보드 핸들러 없음. 장래 인풋 구현 시 원본 바인딩 유지 (P1: D/G/R/V + Z power hit + F alt, P2: 대칭)

### 8. Bot level single source of truth (Option A) — `d1728344` + `f63d7aab` + `dabd84a1` + `ca6c8fe3`
**Problem**: Training Controls L1-L5 버튼과 Hyperparameters dropdown 두 곳에서 bot_level 을 관리 → 사용자가 L5 버튼 클릭 후 Start 시 Hyperparameters 의 기본값 1 로 silent reset. PM 재현 확인.

**PM 결정 (2026-04-12)**: Option A — `status.botLevel` 이 유일한 진실.

**Fix**:
- **WS `training:start.bot_level` Optional** (`d1728344`): omit 시 dispatcher 가 `status.bot_level` 을 carry over. 기본값 1 reset 회귀 방지
- **FE single source** (`f63d7aab`): Training Controls + Hyperparameters 양쪽이 `status.botLevel` 를 읽음. Dropdown 이 더 이상 별도 store 보유 하지 않음
- **Contract lock test** (`dabd84a1`): (1) dashboard `training:start` payload 가 bot_level 을 omit 하는지 + (2) L-buttons 이 stopped state 에서 clickable 유지되는지 불변 보호
- **Lint 정합** (`ca6c8fe3`): `installFetchRouter` fetch mock `_init?: RequestInit` drift 에서 `@typescript-eslint/no-unused-vars` 회피

### 9. `scripts/promote.sh` backend restart — `63e29b58`
**Problem (incident)**: v0.2.3 배포 시 `promote.sh` 가 frontend bundle rsync 는 수행하지만 backend container 재시작은 누락 → FE 는 새 bundle 을 서빙하면서 BE 는 옛 이미지로 응답. PM 의 live UI 테스트에서 "FE 에 새 코드 보이는데 API 응답은 구코드 동작" 으로 탐지됨.

**Fix**: DevOps 가 `scripts/promote.sh` 에 backend `docker compose ... up -d --force-recreate backend` step 추가. 자세한 인시던트 기록은 `docs/incidents/20260412-dev-backend-stale.md` (작성 예정).
